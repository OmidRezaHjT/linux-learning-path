# Hardware Basics

## OS
English: **An operating system (OS) manages hardware and software resources and provides services for programs.**
Finglish: **System-operating (OS) manabe hardware va software ra modiriat mikonad va service baraye barname-ha faraham mikonad**

## Firmware
English: **Firmware is the software embedded in hardware that controls its operation. Motherboards require firmware to function properly.**
Finglish: **Firmware (mian-afzar) software-i ast ke dar hardware gharar darad va amal kard-e an ra control mikonad. Motherboard-ha baraye kar kardan-e sahih be firmware niyaz darand**

## BIOS
English: **The old boot method uses MBR and a text menu, but it's not enough for modern systems, which use a two-step boot process.**
Finglish: **Ravesh-e ghadimi-e boot ba MBR va menu-ye matni kar mikonad, ama baraye system-ha-ye modern kafi nist va aghlab az farayand-e boot do marhale-i estefade mishavad**

## UEFI
English: **EFI (Extensible Firmware Interface) started by Intel in 1998 and is now standard. It uses the EFI System Partition (ESP) with FAT. On Linux, it’s at /boot/efi and files have a .efi extension. Each bootloader must be registered.**
Finglish: **EFI (Extensible Firmware Interface) tavasot Intel dar 1998 shoroo shod va alan standard ast. Az EFI System Partition (ESP) ba FAT estefade mikonad. Dar Linux dar /boot/efi gharar darad va file-ha .efi extension darand. Har bootloader bayad sabt shavad**

## PCI
English: **PCI allows the user to add extra components to the motherboard, like internal HDDs (PATA, SATA, SCSI), network cards, audio cards, and more.**
Finglish: **PCI be user ejazeh midahad ta component-ha-ye ezafi ra be motherboard vasl konad, mesl-e HDD-haye dakheli (PATA, SATA, SCSI), card-e network, card-e audio va digar**

## SSD vs HDD
English: **SSDs are faster, quieter, smaller, and use less energy. HDDs are cheaper, offer more storage, and easier data recovery. SSDs have no moving parts and can last 10+ years, while HDDs usually last 3-5 years**
Finglish: **SSD-ha sari-tar, khamosh-tar, koochak-tar va kam-tar energy estefade mikonand. HDD-ha arzan-tar, storage bishtar midahand va data recovery anha asan-tar ast. SSD-ha ghesmat-e movarand nadarand va mitavanand 10+ sal zendegi konand, dar hali ke HDD-ha aksaran 3-5 sal**

## Network cards vs Wireless cards
English: **NICs provide wired Ethernet connectivity via RJ45, while wireless cards enable Wi-Fi access on computers, including industrial devices**
Finglish: **NIC etesal-e kabeli-e Ethernet az tarigh-e RJ45 faraham mikonad, dar hali ke card-ha-ye wireless etesal-e Wi-Fi ra rooye computer-ha, hatta device-ha-ye industrial, momken mikonand**

## GPIO (General Purpose Input/Output)
English: **GPIO allows the computer to control or communicate with other devices.**
Finglish: **GPIO be computer ejazeh midahad ta device-ha-ye digar ra control ya ba anha ertebat bargharar konad**

## Sysfs
English: **Sysfs is a virtual file system in Linux that provides information about hardware and kernel subsystems, and allows configuring devices. It is mounted at /sys**
Finglish: **Sysfs yek system-file-e majazi dar Linux ast ke etela’at-e hardware va subsystems-e kernel ra neshan midahad va ejazeh mide ta device-ha ra config konid. Dar /sys mount shode ast**

## udev
English: **udev is the device manager in Linux that handles /dev. It manages device nodes, reacts to hardware events, and allows custom rules to control device names and actions when devices are connected**
Finglish: **udev manager-e device dar Linux ast ke /dev ra modiriat mikonad. Node-ha-ye device ra control mikonad, be event-ha-ye hardware vasl mishavad va ejazeh mide rules-e custom baraye name va action-ha-ye device dar vaghti ke device-ha vasl mishavand**

## dbus
English: **D-Bus is a message bus system in Linux that allows applications to communicate, coordinate processes, and launch services on demand**
Finglish: **D-Bus yek system-e message bus dar Linux ast ke be application-ha ejazeh midahad ba ham ertebat dashte bashand, process-ha ra coordinate konand va service-ha ra bar asase darkhast ejra konand**

## proc directory
English: **/proc is a virtual filesystem in RAM where the kernel stores settings and properties. It shows information about IRQs, I/O ports, DMA, processes, and network settings**
Finglish: **/proc yek filesystem majazi dar RAM ast ke kernel settings va properties ra dar an zakhire mikonad. Etela’at darbare IRQ-ha, I/O port-ha, DMA, process-ha va network settings neshan midahad**

## Kernel
English: **The kernel needs drivers to work with hardware, which are stored in initrd or initramfs and used during boot**
Finglish: **Kernel baraye kar ba hardware be driver-ha niyaz darad, ke dar initrd ya initramfs zakhire shode va dar boot estefade mishavand**

## Advanced Configuration and Power Interface (ACPI)
English: **ACPI is a standard that lets the operating system control hardware and power management more efficiently than BIOS.**
Finglish: **ACPI yek standard ast ke be system-operating ejazeh mide hardware va power management ra bishtar az BIOS modiriat konad**

## zram
English: **zram is a Linux kernel module that creates a compressed block device in RAM, which can be used as swap space or for temporary storage. It improves performance on systems with limited memory by reducing I/O to slower disks.**
Finglish: **zram yek module-e kernel-e Linux ast ke yek block device feshorde dar RAM misazad, ke mitavanad be onvane swap space ya storage-e temporary estefade shavad. Performance system-ha ba memory mahdood ra ba kam kardan-e I/O be disk-ha-ye slow behtar mikonad**

## Hypervisor (VMM)
English: Software that creates, runs, and manages virtual machines.
Finglish: Narm-afzari ke Virtual Machine-ha ro eijad, ejra va modiriyat mikone.

## Type 1 Hypervisor
English: Runs directly on physical hardware (bare-metal), without a host operating system.
Finglish: Mostaghim ruye hardware ejra mishe va be host OS niaz nadare.

## Type 2 Hypervisor
English: Runs as an application on a host operating system and manages guest virtual machines.
Finglish: Ruye host OS be onvan yek barname ejra mishe va VM-ha ro modiriyat mikone.

## X11 Architecture
English: The Linux GUI stack has layers: hardware (monitor) → kernel/drivers → Display Server (X or Wayland) → window manager/desktop environment. X (X Window System / X11) is a network-transparent protocol describing how a client (application) and the display server exchange messages. X.Org is the free/open-source implementation of it.
Finglish: Stack-e GUI-e Linux chandin layer dare: hardware (monitor) → kernel/driver-ha → Display Server (X ya Wayland) → window manager/desktop environment. X (X Window System / X11) ye protocol-e network-transparent-e ke tosif mikone chetori client (application) va display server ba ham message rad-o-badal mikonan. X.Org pi'ade-sazi-ye free/open-source-e in protocol-e.

## /etc/X11/xorg.conf
English: The traditional main config file for X. Modern X mostly auto-configures itself and doesn't need this file, but it can still be used to customize boot behavior. Generate one with Xorg -configure, then move it into place. It's divided into sections:
    Files — font paths X needs
    Module — extra modules to load (e.g. glx for 3D)
    InputDevice — keyboard, mouse, touchpad definitions
    Device — graphics card definition
    Monitor / Screen — display specs, resolutions, color depths
    ServerLayout — ties everything together (which screen + input devices are active)
Finglish: File-e config-e asli-e sonati-e X. X-e modern bishtar khodesh ro auto-configure mikone va be in file niazi nist, vali hanuz mishe barash boot behavior ro customize kard. Ba Xorg -configure ye file besaz, ba'ad jaash bezar. Be chand section taghsim mishe:
    Files — mesir-e font-hayi ke X niaz dare
    Module — module-haye ezafi baraye load (masalan glx baraye 3D)
    InputDevice — ta'rif-e keyboard, mouse, touchpad
    Device — ta'rif-e graphics card
    Monitor / Screen — moshakhasat-e display, resolution, color depth
    ServerLayout — hame chiz ro be ham vasl mikone (che screen va input device-i faal-e)

## /etc/X11/xorg.conf.d/
English: Instead of editing the vendor's main xorg.conf directly (which risks being overwritten on updates, or blocking updates to preserve your edits), local customizations go into separate files under this directory. The main xorg.conf stays untouched.
Finglish: Be jaye edit-e mostaghim-e xorg.conf-e asli-e vendor (ke risk-e overwrite shodan moghe update, ya jelogiri az update baraye hefz-e taghirat-e local ro dare), taghirat-e local tooye file-haye jodagane zir-e in directory gozashte mishan. xorg.conf-e asli dast-nakhorde mimune.

## ~/.xsession-errors
English: Log file where errors during X's startup or runtime are recorded — the first place to check when a GUI session fails.
Finglish: File-e log-i ke error-haye moghe startup ya runtime-e X toosh sabt mishan — avvalin ja baraye check kardan vaghti session-e GUI fail mikone.

## DISPLAY variable
English: An environment variable telling graphical programs where to send their output. Default is :0 (the local display). Setting it to a remote server's address (e.g. export DISPLAY=192.168.42.80:0) sends the GUI output there instead — though most distros block remote X connections by default for security.
Finglish: Ye environment variable ke be barname-haye graphical mige khoroojiashun ro koja beferestan. Default-esh :0-e (display-e local). Set kardanesh be address-e ye server-e remote (masalan export DISPLAY=192.168.42.80:0) khorooji-ye GUI ro be oonja mifereste — vali bishtar distro-ha be soorat-e default connection-haye remote-e X ro be dalil-e amniat mibandan.

## Wayland
English: A modern replacement for X11, built to fix X11's age and complexity. Wayland is more secure and simpler to maintain, and many distros now use it by default while keeping X11 as a fallback.
Finglish: Ye jaygozin-e modern baraye X11, ke baraye fix kardan-e ghadimi budan va pichidegi-ye X11 sakhte shode. Wayland amniat-e bishtar va maintenance-e sadetari dare, va kheili az distro-ha alan be soorat-e default azash estefade mikonan va X11 ro be onvan-e fallback negah midaran.

## Remote Desktop Protocols
English: Several protocols let you connect to a GUI remotely:
    X Forwarding (SSH) — runs a GUI program on a remote SSH server but displays it locally (ssh -X)
    VNC (Virtual Network Computer) — cross-platform, uses the RFB protocol, default port is 5900 + display number (usually 5901). Flexible but lacks strong security.
    Spice — open-sourced by RedHat in 2008, mainly used to connect to KVM virtual machines, fast and low CPU usage
    RDP (Remote Desktop Protocol) — used via tools like Xrdp, default port 3389, encrypted by default, many free clients available
Finglish: Chandin protocol vojud dare ke ejaze mide be ye GUI remote connect koni:
    X Forwarding (SSH) — ye barname-e GUI ro rooye ye server-e SSH-e remote ejra mikone vali local display mikone (ssh -X)
    VNC (Virtual Network Computer) — cross-platform, az protocol-e RFB estefade mikone, port-e default 5900 + shomare-ye display-e (maamoolan 5901). Flexible-e vali amniat-e ghavi nadare.
    Spice — RedHat sal-e 2008 open-source-esh kard, bishtar baraye connect be virtual machine-haye KVM estefade mishe, sari' va CPU-e paeen
    RDP (Remote Desktop Protocol) — az tarigh-e abzar-hayi mesle Xrdp estefade mishe, port-e default 3389, be soorat-e default encrypted-e, kheili client-e raygan mojude

## Accessibility Technologies
English: Linux offers three categories of accessibility support, available in display managers and major desktops (GNOME, KDE, XFCE):
    AccessX — helps people with physical/motor difficulties use keyboard and mouse
    Visual Settings — helps people with vision problems (magnification, high contrast, large text)
    Assistive Technologies — text-to-speech (TTS), screen readers, and similar tools for visually impaired users
Finglish: Linux se daste az accessibility support dare, ke tooye display manager-ha va desktop-haye asli (GNOME, KDE, XFCE) mojude:
    AccessX — be afrad-i ke moshkel-e fiziki/harekati daran komak mikone keyboard va mouse ro estefade konan
    Visual Settings — be afrad-i ke moshkel-e binai daran komak mikone (bozorg-namayi, high contrast, text-e bozorg)
    Assistive Technologies — text-to-speech (TTS), screen reader va abzar-haye moshabeh baraye kar-baran-e visually impaired

## GNOME Universal Access Options
English: Found under Settings → Universal Access in GNOME, these are the main configurable options:
    High Contrast — increases contrast between UI elements
    Zoom — magnifies the screen
    Large Text — increases text size system-wide
    Screen Reader — reads screen content aloud
    Screen Keyboard — displays an on-screen keyboard
    Visual Alerts — flashes the screen instead of playing a beep sound
    Sticky Keys — lets you press modifier keys (like Shift) one at a time instead of holding them (e.g. press Shift, then press a → capital A)
    Slow Keys — ignores key repeat unless a key is held for a few seconds
    Bounce Keys — ignores accidental rapid double key presses
    Mouse Keys — lets the numeric keypad arrows control the mouse pointer
    Simulate Secondary Click — right-click by holding down the primary click
    Hover Click — clicks automatically when the pointer hovers over something
Finglish: Zir-e Settings → Universal Access tooye GNOME peida mishan, in option-haye asli-e ghabel-e tanzim hastan:
    High Contrast — contrast beyne elements-e UI ro ziad mikone
    Zoom — safheh ro bozorg-namayi mikone
    Large Text — andaze-ye text ro tooye kolle system ziad mikone
    Screen Reader — mohtava-ye safheh ro bavaz mikhune
    Screen Keyboard — ye keyboard rooye safheh neshun mide
    Visual Alerts — be jaye pakhsh-e sedaye beep, safheh ro flash mikone
    Sticky Keys — ejaze mide modifier key-ha (mesle Shift) ro yeki yeki bezani be jaye negah dashtanshun (masalan Shift bezani ba'ad a → A-e bozorg)
    Slow Keys — repeat-e key ro nadide migire magar in ke key chand sanie negah dashte beshe
    Bounce Keys — feshar-haye do-baare-ye sari' va tasadofi ro nadide migire
    Mouse Keys — ejaze mide arrow-haye numeric keypad, pointer-e mouse ro control konan
    Simulate Secondary Click — right-click ba negah dashtan-e click-e asli
    Hover Click — vaghti pointer rooye chizi mimune, khodkar click mikone

## TTS, Braille & Voice Recognition
English: Additional assistive tools beyond desktop settings:
    TTS (Text-To-Speech) — apps like Orca or Emacspeak read dialog boxes and screen content aloud
    Braille Display — a physical device that outputs text as braille for visually impaired users; TTS/screen readers are often more practical when available
    Voice Recognition — lets users control the OS by voice, increasingly effective and one of the best options for users with disabilities
Finglish: Abzar-haye assistive-e ezafi ghair az tanzimat-e desktop:
    TTS (Text-To-Speech) — app-hayi mesle Orca ya Emacspeak dialog box-ha va mohtava-ye safheh ro bavaz mikhunan
    Braille Display — ye device-e fiziki ke text ro be soorat-e braille khoroji mide baraye kar-baran-e visually impaired; TTS/screen reader aksaran kar-amad-tar-an vaghti mojud bashan
    Voice Recognition — ejaze mide kar-baran ba seda OS ro control kone, roozbe-rooz behtar mishe va yeki az behtarin option-ha baraye kar-baran-e ba ma'looliyat-e
