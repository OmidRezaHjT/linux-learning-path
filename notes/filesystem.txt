## Partitions
English: **In Linux, disks are split into partitions (e.g., /dev/sda1, /dev/sdb5), seen as separate drives. Old BIOS used MBR (max 4 primary + logical inside extended), while UEFI uses GPT (up to 128 partitions)**
Finglish: **Dar Linux, disk-ha be partition taghsim mishavand (mesl-e /dev/sda1, /dev/sdb5) va har kodam manand yek disk-e joda dida mishavand. BIOS az MBR estefade mikard (max 4 partition asli + logical dar Extended) va UEFI az GPT (ta 128 partition) poshtibani mikonad**

## Linking
English: **When writing programs, we use libraries. Linking libraries can be:

Static Linking: The library is included in the executable. The program becomes larger but runs independently of other libraries.

Dynamic Linking: The program depends on external libraries installed separately. This keeps the program smaller, more secure, and allows library updates to improve all programs using it.

Linux dynamic libraries usually look like libLIBNAME.so.VERSION and are in /lib*/ or /usr/lib*/. On Windows, these are called DLLs. Dynamic linking is also called shared libraries because multiple programs share the same library.**
Finglish: **Vaghti barname minevisim, az library-ha estefade mikonim. Link kardan library-ha mitavanad bashad:

Static Linking: Library dar executable shamel mishavad. Barname bozorgtar mishavad vali be digar library-ha moteasel nist.

Dynamic Linking: Barname be library-ha-ye khareji ke joda nasb shode and, moteasel ast. In barname ra koochaktar va amn-tar mikonad va ejaze midahad update-ha-ye library hame barname-ha ra behtar konad.

Linux dynamic library-ha aksaran shabih be libLIBNAME.so.VERSION mibashand va dar /lib*/ ya /usr/lib*/ gharar darand. Dar Windows, be anha DLL migoyand. Dynamic linking hamchenin shared libraries ham gofte mishavad chon chand barname yek library ra share mikonand**

## Symbolic links for libraries
English: **If you are writing a program and you use udev functions, you will ask for a library called libudev.so.1. But a Linux distro, might call its version of udev library libudev.so.1.4.0. How can we solve this problem? The answer is symbolic links; You will learn more about them in the next chapters but for short, a symbolic name is a new name for the same file**
Finglish: **Vaghti barname-i az toabe udev estefade mikonad, momken ast be library-i mesl-e libudev.so.1 niaz dashte bashad. Ama version nasb shode momken ast libudev.so.1.4.0 bashad. Rah-hal, link-e symbolic ast; ke name jadid baraye hamon file ijad mikonad**

## Dynamic library configs and cache
English: **Dynamic linking in Linux is configured using the text file /etc/ld.so.conf. On Ubuntu, it usually points to additional config files in /etc/ld.so.conf.d/, but all entries could also be included directly in the main file**
Finglish: **Link dynamic dar Linux ba estefade az file matni /etc/ld.so.conf config mishavad. Dar Ubuntu, aksaran be file-ha-ye config ezafe dar /etc/ld.so.conf.d/ eshare mikonad, vali hameye khat-ha mitavanand mostaghiman dar file asli gharar girand**

If you change the ld.so.conf (or sub-directories) you need to run ldconfig. Try it with -v switch to see the progress "/" data

## Where OS finds dynamic libraries
English: **When a program needs a shared library, Linux searches in this order: LD_LIBRARY_PATH, program’s PATH, /etc/ld.so.conf (and included files), /lib/, /lib64/, /usr/lib/, /usr/lib64/. You can override defaults by setting LD_LIBRARY_PATH to custom library directories before running a program**
Finglish: **Vaghti barnamei be shared library niaz darad, Linux be tartib dar in masir-ha jostojo mikonad: LD_LIBRARY_PATH, program’s PATH , /etc/ld.so.conf (va file-haye ezafe), /lib/, /lib64/, /usr/lib/, /usr/lib64/. Mitavanid pishfarz-ha ra ba set kardan LD_LIBRARY_PATH be directory-ha-ye library-ye khod pish az ejra-ye barname override konid**

## Loading dynamically
English: **Linux can run programs using a dynamic linker (ld or ld-linux) to load the required dynamic libraries. ELF executables specify this automatically, so you don’t need to run ld-linux manually**
Finglish: **Linux mitavanad barname-ha ra ba estefade az dynamic linker (ld ya ld-linux) ejra kone ta library-ha-ye dynamic mored niaz ra load konad. Executable-ha-ye ELF khodashun moshakhas mikonand ke ba ld-linux ejra shavand, pas niazi be run kardan manual nadarad**

## Filesystem
English: Linux supports several filesystem types, each built for a different purpose:
    ext2 — no journaling, mostly replaced by ext3/ext4
    ext3 — ext2 + journaling (max file 2TB, max fs 16TB)
    ext4 — current standard (max file 16TB, max fs 1EB)
    XFS — journaling, caches to RAM, great with UPS (max size 8EB)
    swap — acts as extra RAM on disk when physical RAM runs out
    VFAT (FAT32) — no journaling, good for Windows exchange, no permissions/symlinks
    exFAT — newer FAT, mainly for USB/external drives, cross-OS compatible
    btrfs — high-performance (max size 16EB), built-in RAID, LVM, snapshots, fault tolerance, live compression
Finglish: Linux az chandin noe filesystem support mikone, har kodoom baraye hadaf-e khodesh sakhte shode:
    ext2 — journaling nadare, bishtar ba ext3/ext4 jaygozin shode
    ext3 — ext2 + journaling (max file 2TB, max fs 16TB)
    ext4 — estandard-e fe'li (max file 16TB, max fs 1EB)
    XFS — journaling dare, cache tooye RAM mizane, baraye UPS aali-e (max size 8EB)
    swap — vaghti RAM-e fiziki tamoom she, mesle RAM-e ezafi rooye disk amal mikone
    VFAT (FAT32) — journaling nadare, baraye exchange ba Windows khube, permission/symlink support nemikone
    exFAT — nasl-e jadid-e FAT, bishtar baraye USB/device-haye external, rooye hame OS kar mikone
    btrfs — performance-e bala (max size 16EB), RAID, LVM, snapshot, fault tolerance, compression-e zende dakhelesh dare

## Inode & Superblock
English: An inode stores all the metadata of a file or directory (owner, permissions, timestamps, and disk block locations), except its name. Directories are basically lists mapping names to inodes.
    Inode — the "identity card" of a file, everything about it except its name
    Superblock — stores metadata about the whole filesystem itself (size, block count, free blocks, feature flags) and is usually backed up in multiple locations on disk
Finglish: Inode tamam-e metadata-ye ye file ya directory ro negah midare (owner, permission, timestamp-ha, va mahal-e block-haye disk), be joz esmesh. Directory-ha dar asl list-i az esm-ha be inode-ha hastan.
    Inode — "karte shenasayi"-ye ye file, hame chiz darbaresh be joz esmesh
    Superblock — metadata-ye kolle filesystem ro negah midare (size, tedad block, block-haye azad, feature-ha) va maamoolan tooye chandin mahal-e disk backup mishe

## FSTAB
English: The /etc/fstab file controls which filesystems are automatically mounted at boot. Each line has 6 fields:
    file system — label, UUID, or device path
    mount point — where it's mounted (or swap/none for swap)
    type — filesystem type like ext4, xfs, nfs
    options — defaults, rw/ro, noauto, user, exec/noexec, noatime, umask
    dump — whether the dump backup utility should back it up (usually 0)
    pass — order of fsck checking at boot (0 = don't check)
Note: user-mounted filesystems default to noexec unless exec is specified after user. noatime disables access-time recording, which can improve performance. After editing fstab, run systemctl daemon-reload to update the systemd units generated from it.
Finglish: File-e /etc/fstab moshakhas mikone che filesystem-hayi khodkar tooye boot mount mishan. Har khat 6 ta field dare:
    file system — label, UUID, ya mesir-e device
    mount point — koja mount mishe (ya swap/none baraye swap)
    type — noe filesystem masalan ext4, xfs, nfs
    options — defaults, rw/ro, noauto, user, exec/noexec, noatime, umask
    dump — ke aya dump utility backuresh begire (maamoolan 0)
    pass — tartib-e check-e fsck moghe boot (0 = check nashe)
Note: filesystem-haye user-mounted be soorat-e default noexec hastan, magar in ke exec ba'ad az user gofte beshe. noatime sabt-e access-time ro ghat mikone ke mituneh performance ro behtar kone. Ba'ad az edit-e fstab, systemctl daemon-reload ro bezan ta unit-haye systemd-e sakhte shode az roosh update beshan.

## UUID & Labels
English: Classical device names like /dev/sdb can change when devices are removed/reconnected, so it's more reliable to identify partitions by their UUID (Universal Unique Identifier) or label. Both mount and fstab can use UUID=... or LABEL=... instead of a device path.
Finglish: Esm-haye classic-e device mesle /dev/sdb mumkene ba disconnect/reconnect avaz beshan, pas motmaentare partition-ha ro ba UUID (Universal Unique Identifier) ya label-eshun beshnasi. Ham mount va ham fstab mitunan be jaye mesir-e device, az UUID=... ya LABEL=... estefade konan.

## Systemd Mount Units
English: When using systemd, a unit configuration file ending in ".mount" describes a filesystem mount point that systemd controls and supervises — an alternative to fstab entries.
Finglish: Vaghti az systemd estefade mishe, ye unit configuration file ke be ".mount" khatm mishe, ye mount point ro tosif mikone ke systemd control va supervise-esh mikone — jaygozin-i baraye entry-haye fstab.

## Hard Links vs Symbolic Links
English: A link is an extra directory entry pointing to a file, letting one file have multiple names.
	Hard link — points directly to the same inode as the original. Both names are equal; deleting one doesn't affect the other, since the data stays until every hard link is removed. Can't cross filesystems or link directories.
	Soft (symbolic) link — points to the target by name, not by inode. Shows as l in ls -l. Can cross filesystems and link directories, but breaks (dangling link) if the target is moved, renamed, or deleted.
	Use ls -i to see a file's inode number — hard-linked files share the same inode number, symlinks don't.
Finglish: Link ye directory entry-e ezafi ke be ye file eshare mikone, ta ye file betuneh chandin esm dashte bashe.
	Hard link — mostaghiman be hamun inode-e file-e asli eshare mikone. Har do esm barabaran; pak kardan-e yeki rooye oon yeki asar nadare, chon data ta vaghti ke hame-ye hard link-ha pak nashan mimune. Nemituneh az filesystem obur kone ya directory link kone.
	Soft (symbolic) link — be esm-e target eshare mikone, na inode-esh. Tooye ls -l be soorat-e l neshun dade mishe. Mituneh az filesystem obur kone va directory ham link kone, vali age target jabeja, esm-avaz ya pak beshe, link kharab mishe (dangling link).
	Ba ls -i mituni shomare-ye inode-e file ro bebini — file-haye hard-linked shomare-ye inode-e moshtarek daran, symlink-ha na.

## Shell Types & Startup Files
English: Bash starts in one of three modes, each loading a different set of config files:
    Login shell (e.g. SSH login) — runs /etc/profile (which runs everything in /etc/profile.d/), then the first found of ~/.bash_profile, ~/.bash_login, or ~/.profile (only one runs), then finally ~/.bashrc.
    Interactive non-login shell (e.g. opening a new terminal) — runs /etc/bash.bashrc (or /etc/bashrc) and ~/.bashrc.
    Non-interactive shell (e.g. a sub-shell spawned to run a command) — no fixed file; checks the BASH_ENV variable, which is usually unset by default.
Other relevant files:
/etc/skel — template directory copied into every new user's home directory.
~/.bash_logout — runs on logout from a login shell, often just clears the screen.
Finglish: Bash be yeki az se hallat shoru' mishe, har kodoom ye set-e file-e config-e mokhtalef load mikone:
    Login shell (masalan SSH login) — /etc/profile ejra mishe (ke hame chi tooye /etc/profile.d/ ro ham ejra mikone), ba'ad avvalin file-e peida shode az ~/.bash_profile, ~/.bash_login, ya ~/.profile (faghat yeki ejra mishe), va dar akhar ~/.bashrc.
    Interactive non-login shell (masalan baz kardan-e terminal-e jadid) — /etc/bash.bashrc (ya /etc/bashrc) va ~/.bashrc ejra mishan.
    Non-interactive shell (masalan sub-shell-i ke baraye ejra-ye ye command sakhte mishe) — file-e sabet nadare; variable-e BASH_ENV ro check mikone, ke maamoolan be soorat-e default unset-e.
File-haye marboote-ye dige:
/etc/skel — directory-e template-i ke tooye home directory-e har user-e jadid copy mishe.
~/.bash_logout — moghe logout az login shell ejra mishe, aksaran faghat safheh ro pak mikone.
